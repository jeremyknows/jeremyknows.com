## Rule of thumb
If something is:
- **Brand doctrine** → update the workspace docs first
- **Site implementation** → update this repo
- **GitHub profile presentation** → update `~/projects/jeremyknows`

## Why this split exists
The workspace is the studio.
The project repos are the public-facing outputs.
That keeps the public repos clean while preserving the full working context elsewhere.
